# Model and Provider Selection

Research date: 2026-11-10. Sources are dated inline; nearly all are from 2026.

## Bottom Line

No public leaderboard predicts which model wins on a client's task. Use public data to pick a short list, then let paired experiments decide. Rankings reverse when the harness changes: one 2026 study moves Claude against GPT by 38 points on Terminal-Bench 4 between two harnesses. The "experiment" is really a (model, effort level, provider) triple. Effort level changes cost and latency more than sampling settings do, and on current Claude models sampling settings are locked. The provider changes quality, structured-output behaviour and data retention, not only speed. Good machine-readable sources exist today: Artificial Analysis (AA) Data API, OpenRouter models and endpoints APIs, models.dev, and Kiln's own model list. Code could fetch them at start-up, but the tuner's gateway gives loop agents only model names, thinking levels and the structured-output mode. The model guide and provider guide should be split. Stable selection rules can go in a skill. Volatile, dated rows should be fetched or generated per run, partly because of the AGENTS.md rule against measured numbers in `agent_files/`.

## Key Findings

- **Model and harness are a pair (strongly confirms overview 6.2 and 6.4).** Four independent 2026 studies agree. Model rankings reverse across harnesses ([arXiv 2610.00917](https://arxiv.org/html/2610.00917v1)). Harness fixes for one small model "do not cleanly transfer" to another ([CMU, arXiv 2607.08938](https://arxiv.org/html/2607.08938)). A harness evolved on a weak model also lifts a strong one, 84.4% to 93.6% ([arXiv 2609.09134](https://arxiv.org/html/2609.09134)). Per-model harness profiles gave +10 to +20 points on τ²-bench ([LangChain, 2026-04-29](https://www.langchain.com/blog/tuning-deep-agents-different-models)). This supports "lock the model, tune, re-scan". It adds one point: a re-scan winner from another family needs a short re-tune.
- **Credible agentic sources and how strong each is.** The strongest independent sources are the AA Intelligence Index v5 (60% private test sets; also gives cost, time and tokens per task), MCP-Atlas, Toolathlon-Verified and τ³-bench banking. BFCL v4 has not been updated since 2026-04-12. Do not use SWE-bench Verified: OpenAI stopped reporting it because of flawed tests and contamination. Do not use LMArena for agent selection. Aggregator sites mix self-reported numbers and different metrics. Independent boards lag new releases by weeks, and top scores sit within about ±2 points. So the guide needs tiers and an evidence level per entry. See [benchmarks-and-leaderboards.md](./benchmarks-and-leaderboards.md).
- **Effort level is part of the candidate.** DeepSeek V4.1 Flash 1017 scores 33 on the AA v5 index at max effort. It takes 48 s to the first answer token and uses 174M output tokens (rank 25 of 26 on verbosity). At high effort it scores 29 and takes 22 s. With reasoning off it scores 19 and takes 1.3 s ([AA](https://artificialanalysis.ai/models/deepseek-v4-1-flash-1017)). This confirms the overview's "reasons a lot, not fast" and names the lever.
- **Sampling settings are mostly not levers now.** On Claude 5.x, Opus 4.7 and 4.8, and the Fable tier, any non-default `temperature`, `top_p` or `top_k` returns a 400 error. Opus 5.5 cannot turn thinking off ([Anthropic thinking docs](https://platform.claude.com/docs/en/build-with-claude/thinking)). Kimi K3 and DeepSeek V4.1 recommend temperature 1.0. Qwen 3.8 has different presets for each mode and needs `top_k` and `presence_penalty`. Kiln's run config cannot set those two. Kiln always sends temperature and top_p. I could not confirm the overview's DeepSeek low-temperature case.
- **Structured-output mode belongs to the (model, provider) pair.** Kiln's model list records that OpenRouter's Fable lanes ignore `json_schema` while reasoning is on. It also records that OpenAI rejects `reasoning_effort` with tools on chat completions, so Kiln turns off tools on that lane for GPT-6.1 Sol. A provider switch is an experiment. See [model-families-and-settings.md](./model-families-and-settings.md).
- **Overview claims about model families, checked.** "Gemini is much better at PDFs" is contested. On GDP.pdf the confidence intervals overlap, and later boards put GPT-5.5 and Opus 4.8 above Gemini 3.1 Pro ([arXiv 2607.11192](https://arxiv.org/html/2607.11192v1); [Surge](https://surgehq.ai/blog/gdp-pdf-can-100b-ai-models-master-the-documents-that-run-the-world)). "Opus best at coding" is partly true: the Fable tier now ranks above Opus, and the order depends on the harness. "Never use an older version" holds as a default. But a version change is a harness change (Opus 5.5 changed defaults and removed options), and a new open model is unstable on third-party hosts in its first week. Open-weight models (GLM 5.3, Kimi K3, Qwen 3.8) are now in the top tier on tool-use boards.
- **Provider facts, checked.** Speed belongs to the host and model together. One model showed a 10× spread across hosts. Cerebras leads on throughput, and Groq is fast, but both serve only a few models and have tight rate limits. In one snapshot Together was faster than Groq on gpt-oss-120b. Cloudflare is slow on throughput and has a small context on some models. Its first-token latency at the edge is low. See [providers-and-routing.md](./providers-and-routing.md).
- **ZDR depends on provider, model and feature together.** OpenRouter's table lists Groq, Cerebras, Fireworks, Together, Vertex, Bedrock and Azure as zero-retention. Anthropic keeps data 30 days and Google AI Studio 55 days. First-party DeepSeek may train on prompts. Anthropic's Fable and Mythos models "require 30-day data retention and are not available under ZDR". The Batch and Files APIs are not ZDR ([Anthropic](https://platform.claude.com/docs/en/manage-claude/api-and-data-retention); [OpenRouter](https://openrouter.ai/docs/guides/privacy/provider-logging)).
- **OpenRouter gotchas.** The same model id can behave differently on different hosts. One user reports a 20+ point τ-bench gap on a DeepSeek V4 Flash third-party host. Tool-call parsers cause this more than quantization does. Variance is worst in a model's first week. Some failures return HTTP 200 (`content: null`, ignored `reasoning.effort`). Pinning providers with fallbacks off caused a full outage for one user. Auto Exacto (on by default for tool calls since 2026-03-12) cut GLM-5 tool-call errors by 88% ([OpenRouter](https://openrouter.ai/blog/announcements/auto-exacto); [Pinggy](https://pinggy.io/blog/openrouter_production_provider_routing_pitfalls)). **Kiln-specific (from code):** Kiln sets a fixed `provider.order` on every OpenRouter request and never sends `zdr`. Per OpenRouter's docs, setting `order` bypasses default routing, so Kiln probably does not get Auto Exacto. I inferred this and did not test it.
- **Machine-readable sources exist. The tuner does not use them yet.** Available sources: AA free API (indexes, prices, speed, cost per task; 1,000 requests a day; attribution required); OpenRouter `/models` and `/endpoints` (pricing, supported parameters, quantization, uptime, latency and throughput percentiles); models.dev `api.json` (prices, limits, parameter support; Kiln's web UI already reads it); Kiln's `kiln_config_v2.json` (`featured_rank`, `editorial_notes`). The gateway's `ModelView` carries only provider, model, name, thinking levels and structured-output mode. See [machine-readable-sources.md](./machine-readable-sources.md).
- **Missing from the overview.** (1) The candidate unit is a (model, effort, provider) triple. (2) The quality of an open model depends on the host. (3) The first-week rule. (4) Index versions are not comparable across versions. (5) Cost per task and time per task are better measures than per-token price and tokens per second. (6) Model-level and feature-level data-retention exceptions. (7) Vendor prompting and migration guides are a cheap source of model-specific harness changes. (8) Decision models need their own row type (models.dev `?type=decision`; OpenRouter `/api/alpha/decisions`).

## Open Questions / Gaps

- I did not run the APIs. The AA, OpenRouter and models.dev field lists come from their docs and from third-party notes. I did not check them against live responses.
- I could not confirm the overview's DeepSeek case ("needed a lower temperature for reliable tool calls and JSON"). Current DeepSeek cards recommend 1.0.
- I did not test whether Kiln's fixed OpenRouter `provider.order` turns off Auto Exacto. The docs suggest it does.
- No source gives a document-count or pass-rate threshold for choosing a model class. The overview's "about 20% propensity" rule has indirect support only.
- I found no machine-readable field for creator country, which the "no Chinese models" restriction needs. A small manual mapping is needed.
- Many numbers here come from secondary write-ups that cite AA or vendor posts (Taskade, kingy.ai, Pinggy, fleeceai, gpuwerk). I flagged these inline. The AA model pages and the OpenRouter docs were read directly.
- Out of scope, noted for other subtopics: the Kiln gaps (no `top_k` or penalties in the run config, no OpenRouter `zdr` or `sort` controls, and the gateway drops model capability fields) belong to "Kiln capability gap". Decision models as a lever belong to "Architecture levers".
