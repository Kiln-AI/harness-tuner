# Backlog: CLI onboarding

Open items found while building the project. The last phase in `implementation_plan.md` closes or dismisses each one.

- [x] `StdTerminal.open_url` (onboarding/terminal.py) calls `webbrowser.open` before printing the URL. On a headless Linux shell (SSH, no DISPLAY, TERM set) Python's webbrowser can run a console browser such as lynx or w3m in the foreground, which blocks and hides the URL until the user quits it. Print the URL first, and decide whether to skip console browsers. Closed in phase 6: `RichTerminal.open_url` (onboarding/console.py) prints the URL first, and opens a browser only on macOS, Windows, or with `DISPLAY` or `WAYLAND_DISPLAY` set; elsewhere it prints the link to open.
- [ ] A malformed `--kiln-host` (e.g. `http://[::1`) crashes with a raw `httpx.InvalidURL` traceback, because `KilnClient.call` catches only `httpx.HTTPError`. The Kiln check now runs first, so it's the first thing a mistyped host hits. Validate `--kiln-host` in argparse, or catch `httpx.InvalidURL` in the client.
- [ ] `write_copy` (onboarding/demo.py) copies everything except `__pycache__`. In a clone where someone used the packaged demo in place, Kiln writes `tasks/**/runs/` and the loop can write `assistant_memory/`, and `--demo-project` would copy those task runs, eval runs and memory records into the user's fresh project; a copy from the wheel never has them (hatch follows `.gitignore`). Consider `shutil.ignore_patterns("__pycache__", "runs")` plus a test, and decide whether to leave out `assistant_memory/` too.
