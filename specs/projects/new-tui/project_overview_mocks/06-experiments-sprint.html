Running experiments

The section's job is to answer four questions for each experiment in the wave: what is being tried, on which concern, how far along it is, and whether it is working. The current version fails because every row leads with an id and jargon and mixes five number formats on one line. Below: what should be in it, then five ways to draw it.

In the four questions

  • What is being tried: the hypothesis, as the item's title, in plain words. It is the thing a person remembers.
  • Which concern: the same name as its Results card, so the eye can go from one to the other.
  • How far along: build, measure, analyze, then a verdict. Shown as steps, not a word.
  • Is it working: items judged out of planned, and how many it fixed and broke so far, spelled out ("5 fixed · 0 broke"), not "+5 −0".
  • How it ended: in plain words. "Stopped: can't beat its parent", not "futility".

Maybe secondary, dim

  • Kind of change (prompt, skill, tool wrapper, model, thinking) as a small tag.
  • Id (w4-1): needed to match the log and Kiln, so keep it, but last and dim.
  • Spend against its cap: matters when money is tight.
  • Item strip: each judged item as a cell. Lovely, and wide.

Out go to the log or Kiln

  • Check details (generality, judge-copy findings). Show only "rebuilding once"; the log has why.
  • Stop-rule names (futility, residual). Translate them.
  • Chunk numbers ("chunk 2 of 3"). Items judged out of planned says the same thing.
  • Predicted effect from the plan. Interesting once, noise after.
